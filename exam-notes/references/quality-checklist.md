# Quality Checklist

Run this before delivering notes.
The goal is clear, complete, exam-useful notes, not maximum density.

## Coverage
- [ ] Every source concept appears at least once
- [ ] Headings/subheadings are reflected where they carry meaning
- [ ] Definitions, rules, steps, types, formulas, examples, and exceptions are covered where present
- [ ] No important source idea is silently dropped

## Clarity
- [ ] Language is simple enough for a first-time reader
- [ ] Technical terms are defined simply on first use
- [ ] Hard topics are explained simply and clearly, not mechanically
- [ ] Source order is followed unless regrouping improves clarity

## Conciseness
- [ ] Notes are to the point
- [ ] Repetition is removed
- [ ] Minor details are merged where natural
- [ ] Tables/diagrams are used only when they help
- [ ] Examples and memory hooks are used only where they add value
- [ ] The structure is not heavier than the material needs

## Exam Usefulness
- [ ] The notes help the student know what to write in the exam
- [ ] Important formulas, comparisons, or steps are easy to find
- [ ] Formula meanings are clear where needed
- [ ] Common traps are included where useful
- [ ] Memory support is included only where it helps recall

## Final Check
- [ ] A student could read this shortly before an exam and understand it
- [ ] A student could revise quickly from this
- [ ] A student could remember the main points well enough to write an answer
- [ ] A quick final scan did not reveal missed small points
