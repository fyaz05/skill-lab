# Flexible Note Structures

Use these as helpers, not fixed templates.
Pick the lightest structure that still gives clear, complete, exam-useful notes.

---

## Option A: Compact Notes

Best for:
- short source
- one topic or one chapter section
- user wants quick, to-the-point notes

Suggested shape:

```md
## Topic Name
- **Term** (simple meaning)
- Main point / purpose
- Key rule / type / relationship
- Formula or step, if present
- Trap or exam line, if useful
```

Use this by default unless the material clearly needs more structure.
If the user asks for a roadmap or quick review, adapt.

---

## Option B: Notes + Quick Review

Best for:
- chapter-level material
- moderate density
- user wants understanding now and revision later

Suggested shape:

```md
## Main Notes

### Topic Name
- What it is
- Key points
- Steps / types / formula if present
- Trap or confusion if useful
- Exam-ready line if useful

## Quick Review
- Topic -> core point
- Formula -> meaning
- Trap -> correction
```

Keep the quick review short.
It should speed revision, not repeat the full notes.
Keep only core points, formulas, traps, and must-remember lines.

---

## Option C: Roadmap + Notes + Quick Review

Best for:
- large chapter
- multi-topic material
- full syllabus or pre-exam revision pack

Suggested shape:

```md
## Roadmap
- What the material is mainly about
- Topic flow / big-picture order
- Most important areas to remember

## Main Notes

### Topic Name
- Clear meaning
- Key ideas
- Steps / types / formula / comparison if relevant
- Trap / exam wording / memory aid if useful

## Quick Review
- Rapid list of terms, formulas, traps, and must-remember points
```

Keep the roadmap very short.
Do not turn it into a second copy of the notes.
Use this only when the material truly benefits from a big-picture map.

---

## Per-Topic Guidance

For each topic, include only what helps:
- definition or meaning
- purpose or core idea
- steps, rules, or types
- formula with variable meanings
- conditions, exceptions, or edge cases
- comparison
- quick example
- trap
- memory hook
- exam-ready line
- diagram/table only if essential to understanding

Do not force all of these every time.

---

## When To Use Tables

Use tables only when they are shorter or clearer than bullets.

Good use cases:
- comparisons
- classifications
- formula summaries

Avoid tables when:
- two or three bullets are simpler
- the table makes the notes look heavier
- the table becomes wider or more repetitive than bullets

---

## When To Use Diagrams

Use text/ASCII diagrams only when:
- a process is hard to follow in bullets
- a visual relationship matters
- the user asks for diagrams

Avoid diagrams for simple material.
Never add a diagram just for style.

---

## Compression Rules

- keep one idea per bullet where possible
- merge minor supporting details
- shorten textbook wording
- remove repeated explanation
- cut duplicate explanation before cutting concept coverage
- explain hard topics simply, not at length
- prefer what helps recall and exam writing

---

## Exam-Ready Support

Add these only when useful:
- `Exam line:` a short answer-ready statement
- `Trap:` common mistake and correct idea
- `Remember:` a short memory aid

Keep them brief.
If labels make the notes feel heavy, write the same idea plainly without a label.
